## 详细功能评估

### 一、核心播放功能

| 功能点 | 重写难度 | 可行性 | 评估说明 |
|--------|---------|--------|----------|
| Media3 播放核心 | 中 | ✅ 可行 | `just_audio` 基于 ExoPlayer，API 类似，但需验证所有编解码器支持 |
| 随机播放/循环模式 | 低 | ✅ 完美可行 | 纯队列逻辑，无原生依赖 |
| 睡眠定时器 | 低 | ✅ 完美可行 | 纯计时器逻辑 |
| 淡入淡出/交叉淡入淡出 | 中 | ⚠️ 需混合 | `just_audio` 支持淡入淡出，但交叉淡入淡出需自定义 |
| 长音频进度记忆 | 低 | ✅ 完美可行 | 本地存储 + 播放位置记录 |
| 播放状态持久化 | 低 | ✅ 完美可行 | SharedPreferences/Hive |
| 队列恢复 | 低 | ✅ 完美可行 | 纯逻辑 + 本地存储 |

**关键插件**：
- `just_audio`：核心播放器
- `audio_service`：后台播放、MediaSession、通知控制
- `audio_session`：音频焦点管理

### 四、播放体验

| 功能点 | 重写难度 | 可行性 | 评估说明 |
|--------|---------|--------|----------|
| 倍速播放 | 低 | ✅ 完美可行 | `just_audio` 原生支持 |
| 音调调节 | 低 | ✅ 完美可行 | `just_audio` 原生支持 |
| 系统均衡器 | 高 | ❌ 不可行 | 需平台通道调用 Android `MediaPlayer.AudioEffect` |
| 响度增强 | 高 | ❌ 不可行 | 需原生音频处理，Flutter 无现成方案 |
| 响度均衡 | 高 | ❌ 不可行 | 需实时音频分析 + 增益控制 |
| 声道平衡 | 中 | ⚠️ 需混合 | 需平台通道调用 AudioTrack 声道控制 |
| 32-bit 高解析输出 | 高 | ❌ 不可行 | 需原生 AudioTrack + PCM 处理 |

**关键问题**：
- `just_audio` 仅支持系统内置均衡器预设，无法自定义频段
- 响度增强、响度均衡、32-bit 输出等高级音效在 Flutter 生态中**完全缺失**

| 功能 | 原因 | 建议方案 |
|------|------|----------|
| **USB 独占播放** | 需 NDK + USB Host API + 原生音频管线 | **保留原生模块**，MethodChannel 调用 |
| **桌面小组件** | Flutter 无法生成 AppWidget | **保留原生小组件**，MethodChannel 通信 |
| **系统级歌词**（悬浮/状态栏/SuperLyric/Lyricon） | 需系统权限/厂商私有 API | **保留原生模块**，平台通道控制 |
| **高级音效**（均衡器/响度增强/响度均衡/32-bit 输出） | 需原生 AudioEffect/AudioTrack | **部分保留原生**，或功能降级 |
| **崩溃捕获**（JVM/Native/ANR） | 需原生 ExceptionHandler/信号处理 | **原生壳兜底**，Flutter 层只做 UI 展示 |
| **启动器快捷方式** | 需原生 ShortcutManager | **原生 Shell 实现**，MethodChannel 触发 |

---

## 推荐架构

```
Flutter UI 层
    ↓ MethodChannel
Android 原生壳（最小化）
    ├── 播放核心模块（ExoPlayer + USB + 音效）
    ├── 系统集成模块（小组件/快捷方式/悬浮歌词）
    └── 安全模块（崩溃捕获/ANR/安全模式）
```

**预计工作量**：
- Flutter UI + 业务逻辑：4-6 个月
- 原生桥接模块：1-2 个月
- 测试与调优：1-2 个月
- **总计：6-10 个月**

**风险提示**：如果无法接受保留原生模块，则 USB 独占、系统级歌词、高级音效、桌面小组件、崩溃安全模式等功能将**完全缺失**。
